# 面试官复盘 · 评价指南

这份文件规定**怎么把一份转录评成一份复盘报告**。配合 [`interview-toolkit.md`](interview-toolkit.md)(HR 的 9 篇面试工具包 rubric)和 [`red-lines.md`](red-lines.md)(合规红线正反案例库)一起用:toolkit 是"标准是什么",red-lines 是"红线怎么判",本文件是"怎么打分、怎么写"。

---

## 0. 立场(最重要,先钉死)

- **评的是面试官的行为,不是候选人。** 候选人答得好不好一律不进报告,只用来反推面试官的提问/追问做得如何。
- **调性是教练式复盘,不是监工打分。** 目的是帮面试官进步。措辞对事不对人,亮点和问题都要给,问题必须能落地改。**对外完全不出现字母评级或 0–100 分数**,用"本场亮点称号"代替——找这场哪个维度最亮眼,不分层级(2026-08-24/08-31 会议要求,见 §3)。
- **正向的必须明确提出来、正向肯定;不好的部分委婉提醒。**(2026-09-01 用户反馈,再次强调)"做得好的地方"要写得肯定、具体,不要轻描淡写；"可以更好的地方"(原"需要改进的地方",已改名)不用"严重度"这种打分式框架，不分高/中、不挂红黄警示色的等级 chip，用提醒的口吻说清楚现象和影响就行，让面试官读了愿意改，而不是觉得被打分。**红线除外**——红线本来就不是"提醒"级别的事，必须继续用最醒目的方式单独标出（见下）；红线区块的措辞也不要说"需要 HR 复核"这种把责任推给下一步流程的说法，直接客观说"出现了 XX 问题，需要注意"就行。
- **每一条判断都要挂原话证据**(带时间戳)。没有原文能引用的判断不要写——这是可信度的命根子。
- **报告开篇以客观数据陈列为主**(面试总时长、说话占比等量化快照),不要一上来就下评判性结论——先摆事实,再给结论。(此条为 2026-08-06 会议方向,终版表述待与磊哥对齐)
- **合规红线优先级最高**(见 [`red-lines.md`](red-lines.md)):命中红线 → 对应维度记 0 分、综合评级直接压至 C 以下,报告里单独醒目标出,不并入普通"高/中"严重度。

## 1. 识别面试官是谁

转录里有两个(或多个)说话人,脚本不区分身份。面试官通常是:
- 开场说"我是面试官 / 你先做个自我介绍"的那位;
- 主要在**问问题**、推进节奏的那位(但注意:说话字数多≠面试官,本项目两场面试官都话多,这本身就是问题)。

确定后,**所有统计和评价都只针对面试官这一方**。候选人的显示名可能是花名(如"云山"),真实姓名从其自我介绍里取。

## 2. 六个评分维度(雷达图 + 六维小结,满分 5)

按 toolkit 归纳出的六维。每维给 0–5 分(可给 0.5),并配一个词的档位标签。

| 维度 | 看什么(对应 toolkit) | 5 分的样子 | 1–2 分的样子 |
|------|---------------------|-----------|-------------|
| **开场与流程** | 结构化·流程标准化;通用技能-记录 | 有公司/岗位/流程介绍,清晰开场,完整收尾 | 无开场介绍、口误、无收尾 |
| **提问质量** | 提问误区 B1–B4;情景/行为/结构化法 | 开放为主、围绕岗位胜任力、不引导不复合 | 连续封闭、引导式、复合式、过于宽泛 |
| **倾听** | 通用技能-倾听(20:80) | 面试官少说多听,给候选人表达和思考空间 | 面试官抢话、长段单向输出、说服而非考察 |
| **追问深度** | 行为面试法 STAR 辨真 | 层层追问挖到细节/量化、能验真 | 浅尝辄止、被 buzzword 糊弄 |
| **尺度把控** | 压力面尺度与流程;判断偏差 A | 施压有框架、对事不对人、无红线 | 无框架质疑、主观偏好之争、针对个人 |
| **反馈体验** | 候选人体验;留提问时间 | 尊重、留提问时间、建设性反馈、维护雇主品牌 | 打断、负面输出、不给提问机会 |

**打分锚点(校准用,别飘)**:
- **5** = 教科书级,可当正面案例;**4** = 明显强项,小瑕疵;**3** = 及格线,有得有失;**2** = 明显短板,反复出问题;**1** = 严重缺失/完全没做;**0** = 踩红线(对应 [`red-lines.md`](red-lines.md) 任意一条,记 0 分,不受其他表现影响;0 分档位专属红线,不是"没做")。
- 打完六维后回看:分数低的维度必须在"待改进"里有对应条目,分数高的必须在"亮点"里有对应条目——**雷达和证据要对得上**,不能雷达画得难看但正文全是表扬。
- **报告展示面不出现 1–5 的具体数字**,雷达图和六维小结只画形状/横条长度 + 档位词(强项/不错/尚可/偏弱/短板);内部仍按 0–5(含 0.5)精细打分,只是不显示给面试官(2026-08-24 会议要求)。

## 3. 亮点称号与判定语(2026-08-31 定稿:找亮点,不分层)

- **不做"整体质量分层"**,称号不是"这场面试官水平几级",而是"这场面试官哪个维度最亮眼"——六维打完分,取**分数最高的那一维**作为本场亮点,称号固定对应该维度,**不随分数强弱换词**(3分和5分同样叫这个称号,只是 `{{BADGE_LINE}}` 这句 flavor 文案按证据现写,程度自然会体现在文案里)。平分按固定顺序(开场与流程→提问质量→倾听→追问深度→尺度把控→反馈体验)取排在前面的那个。**即使六维都很平庸,也照样按最高分选称号发出去**(教练式,先肯定,不设"达标门槛"卡着不发)。

| 维度 | 称号(`{{BADGE_NAME}}`) | 图标(`{{BADGE_SHORT}}`) |
|---|---|---|
| 开场与流程 | 破冰高手 | ⚑ |
| 提问质量 | 灵魂提问官 | ? |
| 倾听 | 最佳听众 | ≈ |
| 追问深度 | 追问达人 | ◎ |
| 尺度把控 | 分寸感在线 | ⚖ |
| 反馈体验 | 暖心体验官 | ♥ |

  - `{{BADGE_SHORT}}` 是 `.verdict .badge` 方块里的**图标字符**,不是文字缩写——上表是固定映射,加上红线状态的 ▦ 共 7 档各对应唯一符号,直接照抄,不要自己另想图标或换成 emoji。
  - `{{BADGE_LABEL}}` 是 `.lb` 那行小字 eyebrow:六个正向称号时固定「本场获得称号」;命中红线时改成「本场请注意」,不能沿用"获得称号"的措辞——命中红线不是一项成就。

  - `{{BADGE_LINE}}`:一句话(20–35字),写这场里这个维度**具体做对了什么**,带细节、挂得上证据,不是套话。例:
    - 追问达人 →「层层追问挖到了三个项目的具体决策依据,候选人的模糊回答基本没能蒙混过去。」
    - 灵魂提问官 →「全场没有一个引导式提问,情景化设计精准戳中候选人的迁移能力。」
  - **命中合规红线 → 不发上述六个称号中的任何一个**,固定改用:`{{BADGE_SHORT}}`=▦,`{{BADGE_LABEL}}`="本场请注意",`{{BADGE_NAME}}`="涉及XX问题"(XX 按实际命中的红线类别现写,如"涉及候选人隐私问题""涉及歧视性提问问题",**不是固定字符串**,不要写成"案件待复核"这种听着像称号的措辞),`{{BADGE_LINE}}`简述触碰了哪条红线,**客观陈述事实,不说"需要和HR复核"这类话**(如"这场提到了候选人的婚育计划，出现了歧视性提问的问题，需要注意")。这不算六个亮点称号里的一档,是独立的复核提醒状态,不参与"哪维最高"的挑选逻辑。图标特意选中性的文件/记录符号(不是警告三角),因为称号卡片本身要保持克制,警示色留给下面独立的红线告警区块。
  - **称号卡片视觉统一同一套蓝色调**,不因维度或强弱变色;红线本身的警示色留给下面单独的「合规红线告警」区块。

- **内部分档 A/B+/B/C/D(HR 2026-08 确认,只服务两件事:①HR 侧团队整体分布校准 ②"待改进"严重度排序参考——跟上面的亮点称号选择完全脱钩,不是"内部档位决定发哪个称号")**:

| 内部档位 | 分布参考 | 含义 | 判定锚点 |
|---|---|---|---|
| A (优秀) | 20% | 可作标杆 | 六维均分 ≥4.5,无红线 |
| B+ (良好) | 20% | 明显强项 | 六维均分 ≥4.0,无红线 |
| B (合格) | 40% | 基本合格,有明确提升点 | 六维均分 ≥3.0,无红线 |
| C (待改进) | 15% | 需重点辅导 | **以面试误区 + 提问误区红线为评估维度**,或六维均分 <3.0 |
| D (不合格) | 5% | 严重不足 / 关账号 | **只以合规红线为评估维度**(见 [`red-lines.md`](red-lines.md));踩 1 条 C 以下,踩多条或涉人身攻击/歧视/恶意隐私 → D |

- **总分**:六维均分 ×20 仍在内部算,只用于内部分档和排"待改进"严重度顺序,**报告任何位置都不展示这个数字,也不用它决定发哪个称号**。
- **不再有"一句话结论 / 判定语"这个展示环节**(即原来的 `{{VERDICT_TITLE}}` `{{VERDICT_DESC}}` `{{JUDGE_TAG}}` 三个 token 已经退役,2026-08-31 用户反馈:正文顶部不要出现"优点在线,但 XX 是最大短板"这类评价性结论句,不要评价面试官)。`.verdict` 区块现在**只放称号 + 客观描述**(见上方 `{{BADGE_LINE}}` 写法),不再单独抓"最要命的一个特征"当标题。
  - 但**内部**仍然要识别"这场最该改的一点"——不展示,只用来给下面第 5 节"待改进表格"排优先级、给第 6 节"下一步动作"选第一条该覆盖的问题。相当于以前 verdict 标题的分析工作还在做,只是不再写成一句醒目结论摆在最前面。

## 4. 量化快照(KPI,4 个,来自脚本;2026-08-24 会议要求砍掉"最长单段发言")

脚本 `transcript_stats.py` 直接给数,4 个固定 KPI:

| KPI | 取值 | 判定 | 目标线 |
|-----|------|------|--------|
| 面试总时长 | `span` 起止时刻差 | 正职 <20min / 实习 <15min 为 chip bad(红线,见 §5) | 正职 40–60min,实习 20–30min |
| 面试官说话占比 | `speakers[面试官].share_pct` | >30% 偏高(chip warn),>40% 超标(chip bad) | 20% |
| 候选人说话占比 | `speakers[候选人].share_pct` | <70% 偏低 | ~80% |
| 提问结构 | 面试官问句数 : 候选人问句数 | 看开放 vs 反问的比例定 good/warn | — |

进度条:说话占比条宽=占比%,竖线标在目标线位置(20%/80%);总时长卡不做进度条,直接标注"参考 xx 分钟"。

## 5. 亮点 与 待改进 怎么挑

**亮点(3 条,绿色卡片)**:挑面试官真正做对、值得保持的行为。每条 = 一句标题 + 对应 rubric 标签(如"情景面试法""STAR 辨真""候选人体验")+ 一句说明 + 带时间戳的原话。哪怕整体一般也要挖出 3 条真实亮点(教练式,先肯定)。

**可以更好的地方**(原"需要改进的地方",2026-09-01 改名+改表达方式,表格,按重要性从上到下排):每条 = 提醒标题(带小图标 `<span class="rmk">`,不是严重度 chip)+ 一段说明 + 对应标准 + 带时间戳原话证据。**控制条目总数(重要的 2-3 条、次要的 1-2 条即可),只保留最核心的问题**——这条"少而精"仍然有效,内部还是按"高/中"两档掂量优先级、决定排序和要不要写,**但这两档不再对外显示成红/橙 chip**,报告里看不到"严重度""高危"这类字眼,统一是"提醒"的语气(2026-09-01 用户反馈:整体立场是"好的必须正向肯定,不好的委婉提醒",不该用打分式的严重度框架)。
- 标题和说明**要委婉、对事不对人**:不写"XX严重失衡""XX问题",写成"XX可以再调整一下""XX还有提升空间"这类邀请式的措辞;仍然要具体、要点出真实现象，不是把问题模糊化——委婉是语气委婉，不是把事实说轻。
- 原话证据数量:**贯穿全场反复出现的模式**(倾听占比过高、连续封闭提问)要挂 2-3 段不同时间点的例子,证明不是孤例;**性质上只发生一次的事件**(开场没做流程说明)给 1 段就是诚实的,不要硬凑——没有证据支撑的话不写,这条原则优先于"多挂几段"。
- 排序仍按重要性:反复出现、影响考察有效性或候选人体验的核心问题排前面(内部对应"高");局部/偶发/影响较轻的问题排后面(内部对应"中")——这个内部分档只用来排序,不出现在界面上。
- ⭐ **合规红线单独拎出、优先级最高,红线不受"委婉"这条约束**:9 类红线清单及正反案例见 [`red-lines.md`](red-lines.md)。命中直接记 0 分、压评级,并在报告醒目标注(`.redline` 卡片,不是普通提醒行)。红线区块的措辞也要客观直接——**不写"需要 HR 复核"这类把判断推给下一步流程的说法**，直接写"出现了 XX 问题，需要注意"，把发现的事实讲清楚就行。

**提问质量维度的功能边界**:只围绕面试方法论(是否开放提问、是否贴岗位胜任力、有无引导式/复合式等问题)，**不重复 Moka 系统已有的"岗位 JD 关键词匹配提醒"功能**——那是 Moka 的职责，这里只评面试官提问的方式与质量(2026-08-06 会议要求)。

**可自动检测度参考**(挑证据时优先抓 🟢🟡,🔴 靠语义判断,不硬凑):
- 🟢 强:说话占比、复合/连续封闭提问、时长、最长发言 —— 规则化能抓
- 🟡 中:引导式句式("是否意味着/不觉得…吗")、宽泛提问("谈谈你自己")、STAR 追问深度、压力面红线、违规问题 —— 靠语义识别
- 🔴 弱:首因/晕轮/刻板/招聘压力等判断偏差 —— 转录里几乎无痕,转成自评提醒,别硬判

## 6. 下一步动作(4 条)

针对这场最该改的点,给 4 条**可操作**的动作,不要空泛。优先覆盖"高严重度"问题,并留一条"保持优点"。句式:一个动词开头的短标题 + 一句怎么做。
- 例:"把'说服'换成'提问'""倾听比例压到 30% 以内""固定 30 秒开场白""保持这场的优点"。

---

## 7. 跨场趋势(必做:面试趋势图)

单份报告只放**本场**信息(不塞上一场)。但**同一面试官有多场时,必须做面试趋势图**(HR 2026-08 要求):趋势对比放在独立的"成长页 / 看板",不混进单场报告。判断"反复犯的顽疾"(如两场都倾听失衡、都开场口误)是给 HR 做面试官培养的最高价值信号。

---

## 8. 写作口吻

- 中文,口语化但专业;用「」引号;数字用半角。
- 对事不对人:写"倾听占比过高",不写"这个面试官很爱说教"。
- 证据先行:先给原话,再给判断。
- 不夸大、不凑数:没有证据就不写这一条,宁可少一条。
